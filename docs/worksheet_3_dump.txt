P7: ·      อธิบายหน้าที่ของ GPIO และอินเทอร์เฟซที่เกี่ยวข้องกับโมดูลของกลุ่มได้
P8: ·      วิเคราะห์ความสัมพันธ์ระหว่าง Block Diagram, Signal, Interface, Power Domain และอุปกรณ์จริงได้
P9: ·      จัดทำ Interface List และ Preliminary Pin Mapping โดยอ้างอิง Datasheet/Schematic ของอุปกรณ์รุ่นจริงได้
P10: ·      เสนอวิธีตรวจสอบและความเสี่ยงก่อนเริ่มออกแบบ Schematic โดยไม่อ้างผลทดสอบที่ยังไม่ได้ดำเนินการ
P11: ข้อตกลงสำหรับการส่งงาน
P12: ผู้เรียนแต่ละคนได้รับ Google Docs ของตนเองใน Google Classroom ส่วนเนื้อหางานกลุ่มสามารถใช้ร่วมกันได้ แต่คำถามสะท้อนคิดท้ายใบงานต้องตอบด้วยตนเอง โดยระบุบทบาทและสิ่งที่ได้เรียนรู้ตามจริง
P13: ข้อควรระวัง: ห้ามกำหนด GPIO, Voltage, Current, Pinout หรือค่าป้องกันวงจรจากการคาดเดา หากยังไม่มีเอกสารรองรับให้ระบุ “TBR – To Be Reviewed” พร้อมชื่อเอกสารที่ต้องตรวจ และงานคาบนี้ยังไม่มีผลทดสอบฮาร์ดแวร์จริง
P16: กิจกรรม: ทบทวนแบบและกำหนดขอบเขตโมดูล
P17: นำ System Block Diagram จากใบงานที่ 2 มาตรวจทานให้มี Main Board, Expansion Board, อุปกรณ์ภายนอก, ทิศทางข้อมูล และทิศทางไฟเลี้ยงครบถ้วน พร้อมขีดเส้น System Boundary ของส่วนที่กลุ่มรับผิดชอบ
P19: พื้นที่แทรก Block Diagram ที่ปรับปรุงแล้ว (หรือวางลิงก์ไฟล์ diagrams.net / PNG / PDF)
P30: กิจกรรม: ศึกษา Datasheet / Schematic ก่อนกำหนดขา
P31: ระบุรุ่นของอุปกรณ์ที่กลุ่มเลือกจริง ข้อมูลที่ต้องตรวจสอบ และแหล่งเอกสารต้นฉบับ เช่น Datasheet จากผู้ผลิต, Schematic ของบอร์ด หรือ Hardware Design Guide หากไม่มีเอกสาร ให้บันทึกว่า “รอตรวจสอบ”
P33: กิจกรรม: จัดทำ Interface List
P34: เขียนอย่างน้อย 5 อินเทอร์เฟซ ระบุต้นทาง ปลายทาง ประเภทและทิศทางของสัญญาณ สื่อสารกับ Mainboard อย่างไร และมีข้อจำกัดที่ต้องตรวจเพิ่มเติมเรื่องใด
P35: กิจกรรม: Preliminary Pin Mapping
P36: นำสัญญาณจาก Interface List มาจับคู่กับขาบนบอร์ด ESP32-S3 รุ่นที่มีอยู่จริง ให้บันทึกทั้ง “GPIO ที่เสนอ” และ “หลักฐานยืนยัน” ถ้ายังไม่มี Schematic หรือ Datasheet ที่ยืนยันขา ให้ระบุ TBR แทนหมายเลขขา
P38: กิจกรรม: วิเคราะห์ Power Domain และความเข้ากันได้
P40: โจทย์เฉพาะสำหรับแต่ละกลุ่ม
P41: ให้อ่านเฉพาะโจทย์ที่ตรงกับกลุ่มของตนเอง แล้วนำไปใช้ตรวจ Interface List, Pin Mapping และ Power Domain ห้ามคัดลอกสัญญาณตัวอย่างโดยไม่ตรวจรุ่นอุปกรณ์
P46: กิจกรรม: Risk Register และแผนตรวจสอบก่อนต่อวงจร
P47: ระบุความเสี่ยงอย่างน้อย 3 ข้อและวางแผนตรวจสอบอย่างน้อย 3 Test Case โดยอ้างอิง Requirement ของกลุ่มจากใบงานที่ 2 ให้เห็นความเชื่อมโยง REQ-ID → Interface → Test Case → Evidence
P48: ตารางประเมินความเสี่ยง
P50: แผนทดสอบและหลักฐานที่ต้องเก็บในอนาคต
P52: ห้ามบันทึก PASS/FAIL หากยังไม่มีการทดสอบจริง ผลงานวันนี้เป็น Design Review และ Verification Plan ไม่ใช่ Test Report ของฮาร์ดแวร์
P57: คำถามสะท้อนคิด (รายบุคคล)
P58: ส่วนนี้ต้องเขียนด้วยตนเอง ไม่คัดลอกคำตอบจากสมาชิก แม้ส่วนอื่นในเอกสารจะเป็นงานกลุ่ม
P59: ก. อินเทอร์เฟซหรือจุดเชื่อมต่อใดของโครงงานมีความเสี่ยงสูงที่สุด เพราะเหตุใด และมีแนวทางลดความเสี่ยงอย่างไร
P61: ข. ก่อนเริ่ม Schematic ต้องตรวจ Datasheet / Schematic เรื่องใดอีก และจะใช้เอกสารใดตรวจยืนยัน
P63: ค. วันนี้ตนเองรับผิดชอบส่วนใดของงานกลุ่ม และจะปรับปรุงการทำงานอย่างไรในคาบถัดไป
P65: เกณฑ์ประเมินใบงานที่ 3 (50 คะแนน)
P67: เกณฑ์นี้ใช้ประเมินเอกสารออกแบบในคาบออนไลน์เท่านั้น สำหรับงาน 3 ให้บันทึกว่าเป็น “แผนตรวจสอบ” ยังไม่ใช่ผลทดสอบจริง นักศึกษาที่ยังไม่มีเอกสารหรือยังไม่ส่งให้บันทึกสถานะรอตรวจ ไม่สร้างคะแนนแทนหลักฐาน
P68: การส่งงานใน Google Classroom
P69: ให้ส่ง Google Docs ที่สร้างสำเนาแยกตามนักศึกษาในห้อง IoT-B.Sc.2-69 ตั้งชื่อเอกสารว่า W03_รหัสนักศึกษา_ชื่อย่อ_กลุ่ม โดยทุกคนต้องมีเนื้อหางานกลุ่มและคำตอบสะท้อนคิดของตนเองครบถ้วน แทรก Block Diagram หรือแนบลิงก์หลักฐานที่ผู้สอนเปิดอ่านได้
